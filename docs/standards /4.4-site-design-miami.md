## 4.4 Miami Site Design

### Site Overview

- **Site:** Miami, FL
- **Users:** 200
- **Role:** Regional branch
- **Routers:** 2
- **Switches:** 2
- **Firewalls:** 1
- **Wireless:** Wireless access points
- **WAN:** Primary enterprise WAN with IPsec backup
- **Routing:** OSPF
- **Internet Access:** Local Internet access through the branch firewall

### VLANs

The Miami site will use VLAN segmentation to separate user,
voice, management, guest, and IoT/printer traffic.

| VLAN | Purpose |
|---|---|
| VLAN 10 | Corporate Users |
| VLAN 20 | Voice |
| VLAN 30 | Management |
| VLAN 40 | Guest |
| VLAN 50 | Printers/IoT |

IPv4 and IPv6 addressing will be defined in the IP addressing plan
and documented in NetBox.

### Routing

Miami will participate in the enterprise OSPF domain.

The primary WAN connection will be preferred during normal operation.
An IPsec VPN tunnel over the Internet will provide a secondary path
to the enterprise network.

OSPF path costs will be used to prefer the primary WAN path.

### High Availability

Miami will be designed to maintain connectivity during a single
WAN-path failure.

The primary WAN path will be preferred during normal operation.
An IPsec VPN tunnel will provide a secondary path to the enterprise
network.

Normal operation:

    Miami
       |
    Primary WAN
       |
    Enterprise Network

Primary WAN failure:

    Miami
       X
    Primary WAN
       |
    IPsec VPN
       |
    Enterprise Network

OSPF will dynamically select the available path.

The failure scenario will be tested by intentionally disabling the
primary WAN path and verifying that the backup path becomes operational.

### Security

The Miami firewall will enforce security policy between the internal
network, Internet, guest network, and VPN connections.

Security requirements include:

- Guest traffic isolated from corporate resources.
- Corporate users restricted according to security policy.
- Management access limited to authorized administrators.
- Site-to-site IPsec VPN protected using appropriate authentication
  and encryption.
- Network device administration secured using SSH and centralized
  authentication.
- Logs forwarded to the centralized logging/SIEM platform.

### Centralized Services

Miami will use centralized enterprise services where appropriate,
including:

- Cisco ISE for network authentication and access control.
- NetBox for infrastructure documentation and IP address management.
- SolarWinds for network monitoring.
- Centralized SIEM/logging for security and operational events.

### Site Success Criteria

The Miami site will be considered successfully implemented when:

- Users can reach approved corporate applications.
- Users can access the Internet according to security policy.
- VLAN segmentation is operational.
- Guest traffic is isolated from corporate resources.
- OSPF establishes the required adjacencies.
- Primary WAN connectivity is operational.
- IPsec backup connectivity is operational.
- WAN failure causes traffic to use the backup path.
- Network devices are documented in NetBox.
- Devices are monitored centrally.
- Logs are received by the centralized logging/SIEM platform.
