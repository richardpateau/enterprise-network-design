## 4.5 Ashburn DR/Data Center Site Design

### Site Overview

- **Site:** Ashburn, VA
- **Users:** Infrastructure only
- **Role:** Disaster Recovery / Data Center
- **Routers:** 2
- **Core/Distribution Switches:** 2
- **Firewalls:** 2
- **Servers:** Critical infrastructure and application services
- **WAN:** Primary enterprise WAN with IPsec backup
- **Routing:** OSPF
- **Internet Access:** Controlled Internet access through the firewall infrastructure

### Purpose

The Ashburn site will provide disaster recovery capabilities for
critical enterprise services.

The site will maintain redundant connectivity to the enterprise
network and host critical infrastructure services that can continue
operating if the New York headquarters becomes unavailable.

Ashburn will not operate as a normal user branch. Its primary purpose
is to provide infrastructure redundancy, application recovery, backup
services, and centralized enterprise services.

### Network Segmentation

The Ashburn data center will use separate networks for servers,
management, backup, and other infrastructure functions.

| VLAN | Purpose |
|---|---|
| VLAN 110 | Server Network |
| VLAN 120 | Management |
| VLAN 130 | Backup |
| VLAN 140 | Infrastructure Services |
| VLAN 150 | DMZ |

IPv4 and IPv6 addressing will be defined in the IP addressing plan
and documented in NetBox.

### Critical Services

Ashburn will host or provide redundancy for critical enterprise
services, including:

- DNS
- DHCP
- Authentication services
- Network monitoring
- SIEM/logging infrastructure
- Internal applications
- Backup infrastructure
- Other services required for disaster recovery

The specific services implemented in the lab will depend on available
resources.

### Routing

Ashburn will participate in the enterprise OSPF domain.

The primary WAN connection between Ashburn and the enterprise network
will be preferred during normal operation.

An IPsec VPN tunnel over the Internet will provide a secondary path
if the primary WAN connection becomes unavailable.

OSPF path costs will be used to prefer the primary WAN path.

### High Availability

Ashburn will use redundant network infrastructure to reduce single
points of failure.

The site will include:

- Two routers.
- Two Layer 3 switches.
- Two firewalls operating as an HA pair.
- Redundant connections between routing and switching infrastructure.
- Redundant connectivity to the enterprise WAN.

Normal operation:

    Enterprise Network
          |
      Primary WAN
          |
       Ashburn
          |
    DR Infrastructure

Primary WAN failure:

    Enterprise Network
          X
      Primary WAN
          |
       IPsec VPN
          |
       Ashburn
          |
    DR Infrastructure

The failure scenario will be tested by intentionally disabling the
primary WAN path and verifying that connectivity is restored through
the IPsec backup path.

### Security

The Ashburn firewall infrastructure will enforce security policy
between the enterprise network, servers, management networks, DMZ,
backup infrastructure, and Internet.

Security requirements include:

- Server networks isolated from management networks.
- Backup networks restricted to authorized systems.
- Management access limited to authorized administrators.
- DMZ services isolated from internal server networks.
- Site-to-site IPsec VPN protected using appropriate authentication
  and encryption.
- Network device administration secured using SSH and centralized
  authentication.
- Security and operational logs forwarded to the centralized SIEM.

### Disaster Recovery

Ashburn will provide a recovery location for critical enterprise
services.

The disaster recovery design will focus on restoring network
connectivity and critical infrastructure services following a major
failure at the New York headquarters.

The project will demonstrate:

1. Loss of the primary WAN connection.
2. Recovery through the IPsec backup path.
3. Continued OSPF routing between sites.
4. Availability of critical services hosted at Ashburn.
5. Monitoring and logging during the failure.
6. Restoration of the primary path after recovery.

The target recovery time for critical services will be **four hours**
for the purposes of this project.

### Centralized Services

Ashburn will integrate with the enterprise management and monitoring
architecture, including:

- Cisco ISE for centralized authentication and access control.
- NetBox for infrastructure documentation and IP address management.
- SolarWinds for network monitoring.
- Centralized SIEM/logging for security and operational events.
- Centralized configuration and automation workflows using Python
  and Ansible.

### Site Success Criteria

The Ashburn DR/Data Center site will be considered successfully
implemented when:

- Critical infrastructure services are operational.
- OSPF establishes the required adjacencies.
- Primary WAN connectivity is operational.
- IPsec backup connectivity is operational.
- WAN failure causes traffic to use the backup path.
- Redundant Layer 3 infrastructure is operational.
- Firewall HA is operational.
- Server, management, backup, and DMZ networks are segmented.
- Critical services remain reachable during a simulated WAN failure.
- Network devices are documented in NetBox.
- Infrastructure is monitored centrally.
- Logs are received by the centralized logging/SIEM platform.
- A documented DR recovery test can be successfully completed.
