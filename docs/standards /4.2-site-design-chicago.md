## 4.2 Chicago Branch

### Site Overview

- **Site:** Chicago, IL
- **Users:** 300
- **Role:** Regional branch office
- **Primary function:** Corporate user access and connectivity to HQ-hosted applications

### Infrastructure

- **Routers:** 2
- **Switches:** 2
- **Firewalls:** 1
- **Wireless:** Enterprise wireless access points
- **WAN:** Primary enterprise WAN with IPsec VPN backup

### LAN Architecture

The Chicago branch will use a segmented LAN design.

Planned VLANs:

| VLAN | Purpose |
|---:|---|
| 10 | Corporate Users |
| 20 | Voice |
| 30 | Management |
| 40 | Guest |
| 50 | Printers / IoT |

The branch switches will provide redundant connectivity to the branch
routing infrastructure where supported.

### WAN Connectivity

Chicago will use two WAN paths:

1. **Primary WAN** — preferred enterprise connectivity to HQ and other
   corporate sites.
2. **IPsec VPN** — backup connectivity using an available Internet path.

The primary WAN path will be preferred during normal operation.

If the primary WAN path fails, routing will converge toward the IPsec
backup path.

### Routing

- **IGP:** OSPF
- **OSPF Area:** TBD
- **Primary path:** Lower OSPF cost
- **Backup path:** Higher OSPF cost

OSPF will provide dynamic routing between Chicago and the enterprise
network.

### Internet Connectivity

Chicago will have Internet connectivity through its local Internet
connection.

Internet access will be subject to the organization's security policy.

Corporate traffic will use the preferred enterprise path, while Internet
traffic will follow the designated Internet-edge/security architecture.

### Security Requirements

Chicago will implement the following security controls:

- VLAN segmentation
- Secure management access
- Centralized authentication through ISE
- Guest-network isolation
- Management-network isolation
- Firewall/security policy enforcement where applicable
- Site-to-site IPsec VPN for backup connectivity
- Centralized logging
- Network monitoring

Guest devices must not be permitted to access corporate or server
networks.

### Monitoring and Management

Chicago infrastructure will be monitored centrally.

Monitoring will include:

- Router availability
- Switch availability
- WAN interfaces
- Interface utilization
- Packet loss
- Latency
- OSPF neighbor status
- Device CPU and memory
- Configuration changes

Network devices will send relevant events to the centralized logging/SIEM
infrastructure.

### High Availability

Chicago will be designed to maintain connectivity during a single WAN-path
failure.

The primary WAN path will be preferred during normal operation. An IPsec
VPN tunnel will provide a secondary path to the enterprise network.

Normal operation:

    Chicago
       |
    Primary WAN
       |
    Enterprise Network

Primary WAN failure:

    Chicago
       X
    Primary WAN
       |
    IPsec VPN
       |
    Enterprise Network

OSPF will dynamically select the available path.

The failure scenario will be tested by intentionally disabling the primary
WAN path and verifying that the backup path becomes operational.

### Site Success Criteria

The Chicago site will be considered successfully implemented when:

- Users can reach approved corporate applications.
- Users can access the Internet according to security policy.
- VLAN segmentation is operational.
- Guest traffic is isolated from corporate resources.
- OSPF establishes the required adjacencies.
- Primary WAN connectivity is operational.
- IPsec backup connectivity is operational.
- WAN failure causes traffic to use the backup path.
- Network devices are documented in NetBox.
- Devices are monitored centrally.
- Logs are received by the centralized logging/SIEM platform.
